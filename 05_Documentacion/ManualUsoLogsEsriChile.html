Lib.esrilogs — Logging profesional para scripts

Este manual describe cómo importar, configurar y utilizar el módulo Lib.esrilogs para generar logs consistentes en archivo y consola, con soporte opcional de salida coloreada mediante rich, rotación por antigüedad y utilidades para registrar DataFrames y tracebacks de error.

Modo archive / wipe

1. Importación del módulo

Básico
Objetivo: importar la clase Logfile desde Lib.esrilogs y preparar el directorio base con Path. 
from Lib.esrilogs import Logfile
from pathlib import Path
Consejo: use Path(__file__).parent para dejar los logs junto al script, o un path centralizado si es un job compartido.

2. Creación del logger

Recomendado

Crea un log con nombre base (sin extensión). El módulo generará /Logs/<nombre>.log. 

generalname = "ActualizarDatos"

logs = Logfile(
    generalname,
    log_path=Path(__file__).parent,
    max_age_days=7,
    rotate_mode="wipe"
)
rotate_mode="wipe" inicia limpio cuando el log supera la antigüedad, sin conservar backups en Old/.

3. Parámetros y rotación

Configuración
Parámetro Tipo Descripción
file_name str Nombre base del archivo log (se agrega .log automáticamente).
log_path Path | str Carpeta base. El módulo crea log_path/Logs.
overwrite bool Si es True, fuerza rotación/limpieza al iniciar.
max_age_days int Días máximos permitidos para el log actual. Si supera, se rota.
rotate_mode str "archive": mueve el log a Logs/Old/<nombre>/ con timestamp.
"wipe": borra el log y comienza limpio (sin crear Old/).
archive
Útil para auditoría o debugging histórico. Mantiene respaldos con fecha/hora.
wipe
Ideal para jobs recurrentes donde solo interesa el log reciente y evitar acumulación.

4. Estructura de carpetas generada

Output
El módulo crea automáticamente Logs/. En modo archive se creará además Logs/Old/. 
/tu_proyecto
 └── Logs/
      ├── ActualizarDatos.log
      └── Old/
          └── ActualizarDatos/
              └── ActualizarDatos-09-02-2026 12-10-22.log
En modo wipe no se crean carpetas Old. Si existían de ejecuciones anteriores, el módulo puede limpiarlas (según tu implementación).

5. Métodos disponibles

API
Método Uso
start_script(msg) Marca el inicio del script / job.
start_funtion(msg) Marca inicio de una función o subproceso.
start(msg) Inicio genérico de etapa.
info(msg) Mensaje informativo de ejecución.
warning(msg) Advertencia (no fatal).
error(msg) Error (marca como ejecución fallida / incidente).
end(msg) Fin de etapa.
close(msg) Cierre del proceso. Calcula duración usando timestamps START/END si existen y la agrega automáticamente. 
logs.start_script("Inicio proceso de carga")
logs.info("Consultando API")
logs.warning("No se encontraron resultados para la fecha")
logs.error("Falló la carga al Image Server")
logs.end("Fin etapa de consulta")
logs.close("Proceso terminado")

6. Registro de DataFrames (debug avanzado)

Debug
Registra el DataFrame en el archivo log manteniendo el formato tabular y removiendo acentos para compatibilidad. 
import pandas as pd

df = pd.DataFrame({"A":[1,2], "B":[3,4]})
logs.dataframe(df)

7. Captura automática de errores

Exception
Use capturaError para registrar mensaje, excepción y traceback completo. Recomendado para bloques try/except. 
try:
    1 / 0
except Exception as e:
    capturaError(e, "Error en cálculo", logs)

8. Consola coloreada (Rich) — opcional

UI
El módulo utiliza rich si está disponible (y puede auto-instalarlo si está habilitado), para resaltar niveles, timestamps y keywords.

Desactivar Rich (forzar salida estándar):

set ESRILOGS_RICH=0

Evitar auto-instalación (mantener import manual):

set ESRILOGS_RICH_AUTOINSTALL=0

9. Ejemplo completo (plantilla recomendada)

Template 
from Lib.esrilogs import Logfile, capturaError
from pathlib import Path

logs = Logfile(
    "ActualizarDatos",
    log_path=Path(__file__).parent,
    max_age_days=7,
    rotate_mode="wipe"
)

logs.start_script("Inicio job de sincronización")

try:
    logs.info("Conectando a ArcGIS Portal")
    logs.info("Descargando imágenes")
    logs.end("Carga de imágenes finalizada")

except Exception as e:
    capturaError(e, "Error general", logs)

finally:
    logs.close("Proceso completado")

10. Buenas prácticas

Standard
  • Un logger por script principal (evitar múltiples archivos simultáneos sin necesidad).
  • Usar start_script() al inicio para dejar marca clara de ejecución.
  • En procesos largos, usar start()/end() por etapas.
  • Siempre ejecutar close() en un finally para registrar duración y cierre limpio.
  • Preferir rotate_mode="wipe" en jobs recurrentes para evitar acumulación de históricos.
  • Preferir rotate_mode="archive" para auditoría y trazabilidad.

11. Recomendación para producción

Ops
Tipo de proceso Configuración sugerida Motivo
Job automático diario / scheduler max_age_days=3, rotate_mode="wipe" Evita acumulación. Mantiene log reciente para soporte.
Proceso crítico / auditoría max_age_days=14, rotate_mode="archive" Conserva evidencia y trazabilidad histórica.
Debug puntual overwrite=True Parte limpio cada vez para analizar una sola corrida.
Recomendación: documente en el encabezado del script el modo elegido (wipe/archive) y la antigüedad (max_age_days) para facilitar soporte.
